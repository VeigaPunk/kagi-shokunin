## Findings

### Medium — existing stamp reader follows a symlinked parent outside `--root`

- **Exploit path:** In an isolated fixture, create an in-root directory symlink to another fixture directory, place a regular file below the symlink, and give its relative path as a stamp row (no absolute path and no `..`). Run the existing `claim-ledger.sh verify` against the fixture. A normal terminal-component check accepts the external target; a mismatching pin exposes a truncated digest and line/byte counts.
- **Evidence:** `corpus/claim-ledger.sh:271-274` canonicalizes the writer's candidate and rejects a resolved path outside root. The read side at `:311-318` checks only absolute names and `..`; `stamp_cmp` at `:339-344` joins `ROOT/path`, rejects a final-component symlink, then hashes and counts it, without checking resolved containment. This asymmetry is also relevant precedent for the new C2 reader.
- **Impact:** The current gate can become an outside-root file metadata/hash oracle if a stamps row and parent symlink are attacker-controlled. It does not print file contents. No external path was created or read for this review.
- **Smallest remediation:** Make read-side resolution symmetric with the writer: refuse a resolved candidate outside canonical root, and preferably open relative to a root directory descriptor with no-follow component traversal, `fstat` a regular file, and hash/count that same opened descriptor. Add a hermetic fixture regression. Do not treat the writer's containment as proof that a hand-edited/read-side row is safe.

### High if unguarded — revision input can turn a read-only `git show` into an option-driven write

- **Exploit path:** If the auditor constructs `git show "$history:corpus/stamps.tsv"` from an unchecked `--history` value, a value beginning with a Git option (notably an `--output=...` form) can be parsed as a Git option rather than as a revision. This can violate the audit's read-only contract. Shell-free argv alone does not prevent option injection.
- **Evidence:** The planned executor contract calls for history lookup through read-only `git show`, and C2 explicitly forbids silent stamp deletion/laundering. No new auditor is present to confirm its argv handling.
- **Impact:** A C2 audit invocation could write a caller-selected path or inspect an unintended tree, invalidating both the safety and historical comparison result.
- **Smallest remediation:** Accept only a full hexadecimal commit object ID (and verify it is a commit), then read the constant path `corpus/stamps.tsv` with a fixed argv and no shell; fail with exit 2 on any invalid/unavailable history. Prefer a read-only plumbing lookup such as `git cat-file` for the fixed blob path. Do not accept a ref/path expression supplied as free-form Git arguments.
- **Parent attack case:** In a temporary repository fixture, pass a history value shaped like `--output=<fixture sentinel>` and assert exit 2 and byte-identical sentinel; also reject option-looking, abbreviated, revision-expression, missing-object, and non-commit inputs. Do not use any real host target.

### High if unguarded — C2 row paths can escape root through path syntax, symlinks, or races

- **Exploit path:** Put absolute, `..`, backslash/drive-style, control-character, duplicate, or malformed paths into fixture `stamps.tsv`; separately point an intermediate component at a fixture file outside root. A lexical-only check or a final-component-only `is_symlink` check can still read outside root. If the implementation resolves a path and later re-opens it by name, swap a component between those steps to exercise TOCTOU.
- **Evidence:** Round-13's recorded sentinel found read-side `../outside.txt` exposure in the earlier ledger and documents the need for the reader to refuse what the writer refuses (`corpus/lessons/round-13.md:108`). Current ledger checks are as above. The new audit's contract requires malformed, duplicate, and escape failures and no host paths.
- **Impact:** A path escaping the repository can disclose file hashes/metadata and can make the historical/current membership report misleading. Duplicate collapse or a malformed row silently ignored can make a dropped pin disappear from the report.
- **Smallest remediation:** Parse TSV with exact field counts and reject empty fields, duplicates, absolute paths (including platform-specific forms), `.`/`..` components, controls, and non-canonical separators before any open. Resolve and prove root containment, refuse symlink components, then use descriptor-relative no-follow opens and hash the same descriptor. Invalid input is cannot-evaluate (exit 2), not an empty/clean comparison. Never auto-restamp or silently normalize away records.
- **Parent attack cases:** (1) Parent-symlink escape to an in-fixture sentinel; (2) final symlink, dangling symlink, directory, FIFO, and missing path; (3) duplicate path with conflicting values and duplicate historical IDs; (4) one dropped old row among otherwise matching rows; (5) malformed row after a valid prefix; (6) file replacement/symlink race where practical in a local fixture. Assert no outside-file bytes/content are read, stable finding IDs, and exit 2 for invalid state.

### High if unguarded — C1 `--claims` or evidence paths become a local-file/network reader

- **Exploit path:** Supply an absolute `--claims` path or a relative path that escapes the explicit fixture/repository root; alternatively put a local `file:` URL, loopback URL, or unapproved source URI in a source field and induce the gate to open/fetch it. A `--root`/`--claims` fallback to the current working directory can also make a missing expected file resolve to an unrelated file.
- **Evidence:** The planned C1 interface accepts a `--root` or `--claims` path. Existing corpus policy prohibits credentials, tokens, sessions, item/field names, and secret references in durable examples (`corpus/QUALITY.md:24`); source rows are a local curated registry (`corpus/SOURCES.md:5-22`), not authorization to fetch caller-supplied URLs. `SOURCES.md:43` explicitly leaves the custom-OIDC workflow sub-page as an unopened lead, so it is not evidence for a release-status claim.
- **Impact:** A supposedly local typed-claim gate could read host-private fixture-external bytes or contact an unintended endpoint, and could leak path/content through diagnostics. Arbitrary claim-provided evidence can also launder unsupported qualifiers into apparent admission.
- **Smallest remediation:** Confine every data path to a canonical explicit root (fixture roots are okay); reject outside-root and symlink escapes before opening. Treat JSON as data only: no shell, eval, dynamic imports, or URL/network fetching. Bind source IDs to a checked-in, reviewed registry entry and fixed source digest/URL; unknown IDs fail closed. Restrict diagnostics to escaped identifiers/rule IDs, never raw claim/source content.
- **Parent attack cases:** Use only temporary fixture files: outside-root `--claims`, symlink-to-outside, missing default file with a decoy in CWD, `file:`/loopback/secret-reference source strings, malformed JSON/UTF-8, duplicate JSON keys, unknown fields and duplicate claim IDs. Assert invalid input cannot become `CLEAN`, no URL is fetched, and no fixture outside root is opened.

## C1/C2 acceptance notes

- For C1, require closed schemas with exact product, named feature/path, feature-specific release status, eligibility/plan, and source-ID binding. Reject missing/unknown qualifiers and cross-product borrowing; do not infer custom-OIDC status from a guide-wide preview label or allow Vault-only evidence to support OpenBao. The comparison must use independent expected decisions and report correct adjudications, not the number of authored rows. Schema validity is not proof of source truth.
- For C2, compare complete validated row sets; preserve each dropped historical stamp as an explicit finding, and distinguish stale/missing current bytes from historical membership. A missing Git history/blob or malformed input is exit 2/cannot-evaluate, not “zero dropped.” Test normal rejection in fixtures and assert zero mutation: no auto-restamp, no output file, no Git index/worktree change. A history lookup must be tied to an immutable commit ID, not a movable ref.
