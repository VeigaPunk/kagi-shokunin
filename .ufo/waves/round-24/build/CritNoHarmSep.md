# Round 24 causal-separability / no-harm review

## Finding

The plan's separation claim (`plans/round-24.md:63-67`) is not true of the measured surfaces as written. `claim-ledger.tsv`, `stamps.tsv`, `SCORECARD.md`, and the citation scan are not merely shared bookkeeping: existing rows measure those files, and C3's mutation harness runs the resulting ledger rows. Keep the three claims distinct by measuring each in its own BASE-derived snapshot, then do a separate final combined verification after all shared populations are frozen.

## Counterexamples and evidence

1. **C1 can mask an operability regression while returning `CLEAN`.** `R18-01` deliberately runs `drift-pins.sh` with expected `DRIFT`/exit 1; its note says the result detects the substrate returning and “must run on every host” (`corpus/claim-ledger.tsv:48`). C1 turns this and other tagged host rows into `HOST-SKIP`. In `claim-ledger.sh:504-519`, a skipped row is not executed; the verify summary can still be `CLAIM_LEDGER: CLEAN` with `host_skipped=N` (`:1090-1095`). Thus, if `drift-pins.sh` regresses to miss drift, the default gate no longer observes it. The output is not literally silent (`HOST-SKIP` is printed), but `CLEAN` can still be mistaken for a complete check.

   The planned tripwire is not a sufficient guard by itself: `host-tripwire.sh:48-61` runs only default `verify`/`cells`, counts host-script log lines, prints each exit/last-line, and computes `total` from the log. It does not fail on an unexpected exit/last-line, assert the exact `HOST-SKIP` ID set, prove ordinary rows still ran, or exercise `--allow-host-rows`. A gate that aborts before executing any host script can therefore satisfy `total=0` (inference from the implementation). C1's policy guard itself is visible at `claim-ledger.sh:164-220`.

   **Smallest safe correction:** retain the default skip, but make the result explicitly incomplete/non-clean whenever host rows were skipped; assert expected command exits, terminal verdicts, and exact skipped IDs in the scratch tripwire. Add a second scratch-only stubbed run with `--allow-host-rows` to show the explicit path still reaches the selected rows. Never run that opt-in against the real host. If default `CLEAN` continues to imply a complete verification, this is an operability tradeoff the canonical judge must not count as “no axis harmed.”

2. **C1 and C3 are directly coupled by `R18-02`.** The current row uses `grep -cE '\[substrate\]'` (`corpus/claim-ledger.tsv:49`); C1's single-backslash rule rejects it (`claim-ledger.sh:258-260`), so C1 must rewrite it as a fixed-string count (for example, `grep -Fc '[substrate]' corpus/claim-ledger.tsv`) for the row to remain runnable. C3 includes `R18-02` in its frozen 15-row population (`plans/round-24.md:51-61`) and its swap/control path evaluates that row (`tools/identity-swap.py:137-152,170-187`). Without C1's rewrite, C3's after control is policy-refused under the new gate. Nuance: adding `[host]` tags alone does not change C3's `ledger-substrate` selector, which hashes only `[substrate]` notes (`corpus/row-identity.sh:83-85`); the coupling is the command-policy rewrite, not an assumed change to that selector's membership.

3. **C2 changes a C3 population.** `R12-03` expects 79 nonblank entries in `corpus/stamps.tsv` (`corpus/claim-ledger.tsv:28`). C2 introduces `rendered-text-v1.py` and `inrow-pins.tsv` and the round requires their provenance to be cited (`plans/round-24.md:33-50`); if these new artifacts are pinned as required by the stamp contract (`claim-ledger.sh:14-18`), the stamp-row count and the `stamps` identity change. C3 explicitly includes `R12-03` and hashes the stamped-path membership (`row-identity.sh:18-22,71-74`; `identity-swap.py:137-152`). Consequently, a C3 control run against C2's final stamps cannot pass with the BASE `R12-03` expectation/digest. Update the `R12-03` count for the settled stamp set, then compute the C3 stamp identity; do not treat the stamp migration as non-coupling.

4. **C3 changes the rows it claims to measure.** `R21-04` currently expects 45 ledger IDs (`corpus/claim-ledger.tsv:54`), while C3 adds R24 identity rows (`plans/round-24.md:55-61`). Every new `R24-*` ID increments that count. If one identity row is added per frozen population row, the expected count becomes at least 60, before any additional C1/C2 ledger rows; the exact final value is `45 + all newly added row IDs` (inference, not executed). The mutation harness includes every `R24-*` row when evaluating a mutation (`tools/identity-swap.py:15-18,170-177`), so these IDs must be settled before `R21-04` and its `ledger-ids` digest are measured. The same self-coupling applies to `R13-01`: it expects 27 `## Round` headings (`claim-ledger.tsv:29`), and the Round-24 pre/post headings add two under the existing convention, making 29 before any further heading change. Its identity selector hashes those full heading lines (`row-identity.sh:25,87-90`).

   **Smallest safe correction:** reserve and add the complete R24 row-ID set first; add the Round-24 scorecard headings; finalize all new stamped paths; then migrate `R12-03`, `R13-01`, and `R21-04` with QM14 old→new records. Only after those populations are stable, generate/pin `stamps`, `scorecard-rounds`, and `ledger-ids` digests and run the identity-swap controls. No later row, stamp, or heading additions may occur without remeasuring these rows.

5. **C1's citation after-measurement also sees C2's work.** The default citation set includes every `corpus/lessons/*.md` (`claim-ledger.sh:619-632`); C2 says the lesson will cite the normalizer (`plans/round-24.md:43-45`). Thus the C1 `citations` result (`plans/round-24.md:23-25,32`) can change when the C2 lesson is added. The assertion that C1's citation count does not read C2 files (`:63-67`) is false for that new lesson. Preserve a C1-only citation result on a C1-only BASE clone, then separately rerun citations on the final combined tree and attribute any new unresolved token to its source file.

6. **The C3 command is not reproducible as frozen.** The plan specifies `bash .ufo/waves/round-24/tools/identity-swap.sh <rev>` (`plans/round-24.md:58-61`), while the current implementation is `tools/identity-swap.py` and documents `LABEL REV [SRC FILE...]` (`tools/identity-swap.py:1-2,24-25`). This is a path and argument-count mismatch at this review snapshot. Reconcile the frozen command with the actual entry point (or add the documented wrapper) before treating its 15/15→0/15 result as runnable. No invocation was attempted.

## Axis impact / no-harm

- **Operability — at risk (C1).** Safe-by-default is valuable, but default skip suppresses R18-01's live return-detection signal. Explicit skipped IDs plus a non-complete status and scratch opt-in proof are the minimum guard; a zero tripwire count alone is not operability evidence.
- **Freshness — bounded (C2).** The planned counts establish capture/provenance classification, not that current page content still supports every knowledge claim. The census contract says captures are point attestations and quote checks are shape-limited (`sources-census.sh:56-75,277-285`). Keep the claim bounded to provenance/normalizer consistency; route any content discrepancy into the affected knowledge entry/source review.
- **Depth — unchanged, not harmed merely by being untouched.** Round-23 post-scorecard explicitly says depth stays 9 and no depth claim is booked (`SCORECARD.md:828-844`). Since C2 does not propose editing knowledge entries, do not claim depth improvement. If a recapture contradicts a knowledge fact, leaving that entry untouched would then be an unaddressed depth/freshness risk, not a neutral outcome.
- **Adjacency — no direct harm found.** C3 mutates adjacency memberships only in scratch clones (`identity-swap.py:144-148`); no shipped `corpus/adjacency.tsv` change is part of the frozen claims. Preserve its per-domain ownership and report any out-of-lane finding rather than folding it into kagi. No coverage change is claimed.
- **Calibration — C3's useful scope is the 15 named count rows only.** It is not a general calibration-accuracy score. The self-referential row/count migrations above must pass before the 15/15→0/15 result can support that bounded claim.
