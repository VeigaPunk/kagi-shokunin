**Axes:** calibration, operability, freshness. **Scope:** C3 public-feed fetches, redirect and parser boundaries, receipts, and rendered quotes. **Frozen revision:** `4587c61a348e4528717404a68912c373f3ef4d03`.

## Findings

**Overall severity: MEDIUM, conditional on unreviewed source/URL data; no live exploit by this reviewer.** The frozen base has no C3 files. I read-only inspected the executor's latest unlanded scratch draft.

1. **Feed provenance is not machine-bound to an official source (MEDIUM, conditional).** Exploit path: a mistaken or malicious row labelled `kind=feed` points at an arbitrary public HTTPS host; a matching clock binding is accepted, and its first feed item may set `fired`. `parse_sources()` retains `kind` but not tier/status (`release-clock.py:55-89`); the feed branch checks only `kind == "feed"` and exact URL equality (`:372-376`). The draft has no S033+ source rows or actual clock bindings, so no concrete official feed host was checked. Impact: an unreviewed public origin can be contacted and supply false freshness evidence. Smallest remediation: retain and require the intended authoritative tier/status and bind feed URLs to reviewed official origins.
2. **Receipt URL path redaction is heuristic (MEDIUM, conditional).** Exploit path: a source/feed URL carries an opaque short path token such as `/share/abc12345`; it matches none of the known route/length patterns, so `safe_receipt_url()` retains it (`:125-140,181-195`). `observe_one()` serializes that URL into the named receipt (`:518-563`). Impact: path-carried secret material becomes durable receipt content (the file is mode 0600, but still persists it). Smallest remediation: receipt only the source ID and/or an exact allowlisted public path, not arbitrary URL paths.

**DNS-rebinding concern from the earlier draft is cleared by the latest source design, not independently tested.** `public_addresses()` rejects every non-global answer and passes the validated addresses into `PinnedHTTPSConnection`; its connection override dials those literal addresses while `HTTPSConnection` retains the URL host for TLS SNI/verification (`:219-268,276-298`). The request loop repeats that check for each redirect (`:436-463`). This removes the prior separate-lookup path in the inspected draft; the executor reports a synthetic test and public SOPS-feed trial, but I did not run either.

## Concrete requirements and falsifiers

1. **Targets and redirects.** Current draft requires HTTPS on port 443, checks public DNS answers, disables automatic redirects, limits manual redirects to the same origin, and restricts 1Password redirects to the starting public path (`:142-217,219-268,276-298,436-463`). **Falsifiers:** a non-feed/low-tier binding is accepted; a cross-origin, downgrade, loopback/private, or disallowed 1Password path receives a second request; a DNS resolver's private address is ever dialed.
2. **Response size/time.** Draft caps `response.read()` at 8 MiB plus one byte for success/error bodies (`:33,464-475`). It has a 20-second socket timeout but no whole-request deadline; a slow-drip response can keep resetting the timeout. **Falsifiers:** a no-length/chunked body exceeds the cap, or a slow drip keeps observation active without a total deadline; either must fail without a receipt.
3. **No auth, cookies, or environment tokens.** Static search of the draft found no `GITHUB_TOKEN`, `os.environ`, cookie-jar, `.netrc`, subprocess, or shell access. `ProxyHandler({})` disables ambient proxy lookup on the inspected CPython 3.14; the draft test traps `getproxies()` and routes a fake HTTPS request (`:263-268,889-926`). No `Authorization` or `Cookie` header is added. **Falsifier:** a synthetic `GITHUB_TOKEN=sentinel`/proxy environment or request capture shows a credential read or auth/cookie/proxy-auth header. Never use a real token.
4. **User-Agent.** Draft sets `kagi-shokunin-round25/1.0 (documentation verification)` (`:32`) on each request (`:447`). **Falsifier:** a request capture observes a missing or different UA on any allowed hop.
5. **Untrusted feed parsing.** Network feeds use Atom/RSS XML (`:477-511`), not JSON; JSON is only used for receipts/tests. The parser rejects DTD/entity declarations and bounds body, element, and entry counts (`:33-35,477-494`). **Falsifiers:** malformed XML, JSON supplied as a feed, DTD/entity payload, or oversized structure produces a version/receipt rather than a bounded failure. Current selftest source includes DTD/limit cases; UNRUN by this reviewer.
6. **Named minimal receipt.** `--observe` requires `OUT.json` (`:1042-1071`); the writer atomically links a same-directory temporary file, refuses existing/symlink destinations, and emits a fixed field set (`:566-597`). The draft tests mode 0600/no-overwrite/symlink behavior (`:943-981`). **Falsifier:** omitting the path writes anything, an existing target/symlink is overwritten, or any body/header/secret-like URL material is serialized. Path heuristic gap is finding 2.
7. **1Password signed-in surface isolation.** S032 is the public docs URL `https://www.1password.dev/brokered-access` (`corpus/SOURCES.md:38`). Draft rejects common account/auth/app/vault host/path segments and only permits same-origin redirects to that starting public path (`release-clock.py:162-175,201-217`); it does not invoke `op`, browser/CDP/handler, or load cookies/profile data. **Falsifier:** a mock redirect to another origin or `/login`, `/account`, `/app`, or another path causes another request. No live 1Password surface was contacted.
