Credential Broker FAQs

What is 1Password Credential Broker?

1Password Credential Broker authenticates machine workloads and AI agents at runtime, then delivers exactly the credentials they're approved for. Workloads prove who they are and get what policy allows, with no standing vault access.

How does 1Password Credential Broker keep secrets secure?

Credential Broker encrypts every secret with two separate keys: an integration key, and one that stays locked inside a confidential computing enclave (an isolated, hardware-protected execution environment) at 1Password. Decrypting a credential requires both keys. Neither party can access a secret on its own.

What gets logged when 1Password Credential Broker delivers a credential?

Every credential delivery is logged with full attribution: which workload requested access and which policy authorized it. Security teams get a complete audit trail for every issuance event.

How does 1Password Credential Broker verify a workload's identity?

Credential Broker verifies a workload's identity using Workload Identity Federation before delivering any credential. Workload Identity Federation is a standard that lets a platform prove which specific job is running without relying on a manually managed service account token. Once verified, the workload receives only the credentials that job is approved for, and nothing more.

Does 1Password Credential Broker work with GitHub Actions?

Yes. Any GitHub Actions workflow can use Workload Identity Federation to prove its identity to 1Password and receive the exact credentials it's approved for. No service account token is required, and every delivery is logged with full attribution.

Is 1Password Credential Broker generally available?

Not yet. Credential Broker is currently in public preview for all Enterprise Password Manager customers, starting with GitHub Actions, and custom OIDC configurations. You can get started by visiting our documentation page here: 1password.dev/environments/credential-broker.
