## Self-improvement suggestions (proposals only, not applied)

1. **A host-safe `verify` mode that automates QM12.** QM12 is a manual ritual: re-run
   every ledger row that touches no host-private surface, `sha256sum --check` the
   stamps, list skipped ids with reasons. A `claim-ledger.sh verify --host-safe`
   that does exactly that (selecting rows by a tag, like `[substrate]`) and prints
   the skipped ids in its verdict line would make QM5/QM12 enforceable at commit
   time. This is the concrete form of the close-out gate I've suggested twice.
2. **A standing fail-open suite for every gate.** For each gate, keep a set of
   adversarial inputs that *should* be rejected (malformed ids, duplicate headers,
   path escapes, tier inflation, Unicode look-alikes, trailing whitespace) and
   require all of them to fail. Run it alongside `--selftest`. The census bugs
   from round 21 were found only because a reviewer thought to try them.
3. **A qualifier check before admission (QA9, made checkable).** For each quoted
   source sentence, have the author list its qualifiers (product, version, code
   path, plan or eligibility, release status) in the entry's citation line, and
   have the census confirm each listed qualifier appears in the citing sentence.
   Also follow feature-specific status links rather than inheriting a page-level
   "preview" label, which is the round-22 debt the verifier named.
4. **Track outside agreement as the calibration number.** Record the verifier's
   admit and reject agreement per round (round 21: admits 0/2, rejects 3/3) in
   the scorecard, and let calibration move only on that, not on counts of rows
   the lane wrote itself. The adjudication already declined C2 for this reason.
5. **Check quotes, not page hashes, for source freshness.** The verifier found
   S005 and S006 had different page hashes within a day of opening, which is
   likely page churn (marketing page, blog), not changed meaning. A recheck that
   confirms the anchored quote is still present, with the raw hash kept as a
   secondary signal, would separate "page moved" from "claim changed."
6. **Make history edits append-only by gate.** The verifier flagged in-place
   rewrites of pinned `claim-ledger.tsv` rows and nine deleted `stamps.tsv` lines.
   A check that compares the ledger and stamp files against the previous commit
   and fails unless every change is an added row or a row that names what it
   supersedes would keep the audit trail honest without anyone remembering to.
7. **Carry-over:** pin the op version used by `--dotenv-bytes` so an upgrade
   forces a re-measure, and widen the byte classes (CRLF, trailing `\r`, UTF-8
   BOM, NUL, `#` inside quotes). The planned round-22 fix to report op-side
   failures as `SETUP` instead of `DRIFT` should land first, so new cases don't
   inherit that ambiguity.
