1. **“Observed” is not “fired”; the acceptance never requires a fire. Severity: HIGH.** The plan says “bound and fired today” (`plans/round-25.md:56-66`), but the stated after criterion is only 28 bound, 0 unbound, and an observation dated 2026-10-21 per row (`:67-71`); `fired=K` has no required K or meaning. Thus a CLEAN receipt with `fired=0` can meet the numeric acceptance. If “fired” instead means every manual `--observe`, this is a scheduled recheck, not an on-release event. **Falsifier:** on a fixture, keep the release identity unchanged and run observe: it must not count as fired; change the feed identity past the recorded baseline: it must count a fire and require the row’s evidence to be rechecked. A real positive claim needs a fired row with old/new release identity and successful post-fire check. **Axes:** freshness, calibration. **Smallest correction:** specify the fire transition and a concrete positive control; report `observed` separately from `fired`, and do not assert every source fired absent an actual release event.

2. **A rendered-quote probe is not a release clock and may miss claim drift. Severity: HIGH.** For unversioned docs, C3 calls a row “fired” when its quote still locates in a fresh fetch (`plans/round-25.md:59-65`), but that proves presence, not a release/version transition. It can miss changed supporting context while the selected phrase survives. Concrete registry examples: S017 teaches both public-preview status and Business-account connection, while its capture quote is only the page H1; S019 teaches GitHub.com/private-repository restrictions as well as setup eligibility, while its capture quote is only the supported-integration sentence (`corpus/SOURCES.md:23-25`; `corpus/source-fetches.tsv:44-47`). **Falsifier:** mutate only an unquoted supporting clause in such a fixture while retaining the selected quote; if observe still counts a fired/reverified row, it gives a false freshness positive. **Axes:** freshness, calibration. **Smallest correction:** either name these `content-quote checks` (not release clocks) and limit the represented claim to the quoted text, or bind each multi-part claim to all relied-on anchors/content and treat changed content as requiring review. A quote-location count alone cannot establish a release event.

3. **Date-only receipt can be self-authored or replayed, with no proof of a fresh fetch. Severity: HIGH.** `--observe` is specified to “record[] a dated observation receipt” and the offline command checks bindings (`plans/round-25.md:63-71`); the contract does not require capture identity, request profile, successful status/final URL, body digest, or independent validation. Existing corpus policy explicitly says a fetch digest is only a point attestation, never a drift pin (`corpus/source-fetches.tsv:37-43`; `corpus/sources-census.sh:56-84`), and the prior lesson disclaims that prior checks bind claim bodies or vendor currentness (`corpus/lessons/round-24.md:273-283`). **Falsifier:** hand-copy a receipt dated 2026-10-21 into a root without fetching anything; `--root` must refuse it. Also replay that receipt on a later date; it must not remain current. **Axes:** freshness, calibration, operability. **Smallest correction:** the observation must be generated by an actual same-run fetch and bind the exact source-row identity, URL/final URL, request/representation profile, response digest, timestamp, and located anchors; offline verification must reject missing/mismatched evidence rather than trust the date field.

4. **Tool verdict risks certifying its own receipt. Severity: HIGH.** The same `release-clock.py` has an offline verdict and an `--observe` mode that records the receipt (`plans/round-25.md:63-66`). The plan does not state an independent authority that checks the receipt’s fetch or quote result. The separate `c3-measure.py` is described as a before/after counter, which does not by itself validate source evidence (`:67-71`). This repeats the known instrument hazard: round-24 withdrew an inference from absence of `FAIL`, and required complete, internally consistent receipts instead (`corpus/lessons/round-24.md:215-219,273-283`). **Falsifier:** mutate the recorded response identity/digest or quote result while preserving its “observed today” date; the offline checker and independent measure must reject it. If both say CLEAN, the result is self-certifying bookkeeping. **Axes:** calibration, freshness. **Smallest correction:** independently recompute receipt integrity/anchor location from captured response bytes (or a separately produced capture), and include a bad-receipt control whose expected failure is literal; do not use the clock tool’s own summary as its evidence.

5. **Clock population mixes admitted evidence with a queued lead and rejected source. Severity: MEDIUM.** The stated N=28 is every `on-release` row, including queued S005 and rejected S008 (`corpus/SOURCES.md:11,14`; total population follows `plans/round-25.md:57-71`). Binding/freshening these does not itself refresh admitted knowledge, while omitting them silently would falsify the exact 28-row count. **Falsifier:** change either row’s status/used-by while retaining its clock receipt; the census must either reject the stale binding or explicitly report the changed population/status, not credit it as knowledge freshness. **Axes:** calibration, freshness. **Smallest correction:** state whether the population is all registry rows or only active mined rows; if deliberately all, report status-stratified counts and avoid implying queued/rejected evidence advances freshness of admitted knowledge.
