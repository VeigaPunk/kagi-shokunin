## Findings (severity order)

**F1 HIGH — C1's canonicality oracle must not be `numeric_version()`.** `corpus/release-clock.py:369-381` is the *strict X.Y.Z* oracle, but the corpus legitimately carries non-strict tokens: the S012 row anchor `v1.21.x` (`corpus/release-clocks.tsv:13`) and the registry anchor tokens `1.17` (S012,S022), `4.6` (S030), `11.2` (S042) (`corpus/SOURCES.md:18,28,36,49`). A check built on it invalidates S012 → `observed 30→29, fired 3→2` → R25-04's pinned line breaks. The predicate must be exactly "no leading zero in a multi-digit component AND no component longer than the int-string limit", must skip the `-` placeholder of rendered-quote rows, and must accept series/prerelease anchors. (Measured: a strict-X.Y.Z oracle flags S012 + those 4 tokens.)

**F2 HIGH — C2 must read the feed row's ANCHOR cell (`SOURCES.md` `cells[5]`, parsed at `corpus/release-clock.py:81-86`) and be restricted to `derived:` rows.** Traps: S037's *teaches* cell names two versions `8.23.0` and `8.23.1` (curl's DEV label, `corpus/SOURCES.md:43`); S029's *own* anchor cell names `8.23.1`, not its row's `8.23.0` (`corpus/SOURCES.md:35`); S033/S034/S035 each name their version twice (title + tag link) → "the version" is the set of *distinct* versions, not a token count. Measured: all 15 `derived:` rows satisfy the rule as specified → C2 as written keeps CLEAN30. A blanket rule over *all* feed rows breaks exactly S012 (anchored `v1.21.x`, feed S034 → `2.2.0`).

**F3 HIGH — the summary line is pinned byte-exactly; C1/C2 findings must be new error lines.** R25-04 (`corpus/claim-ledger.tsv:83`) pins `^RELEASE_CLOCK: CLEAN \(on_release=30 bound=30 unbound=0 observed=30 fired=3 derived=15\)$`; `print_result` (`:644-650`) prints one `CATEGORY row_id` line per finding then that summary. A new key / reordered keys / renamed state word breaks R25-04; a finding must appear only as a `CATEGORY row` line. The six counts stay 30/30/0/30/3/15.

**F4 HIGH — a canonicality/derivation defect is exit 1 (failed claim), never exit 2 (SETUP).** `SetupError` is "not a failed claim" (`corpus/release-clock.py:42-43`); routing the defect through `setup()` yields exit 2 and fails the frozen predicate ("exits 1"). State word `FAILED`, same six keys.

**F5 HIGH — frozen C1 fixture F1 is masked by the pinned receipt; as written it does not discriminate BASE from the fix.** With the pinned round-26 receipt, editing only `corpus/release-clocks.tsv` (S040 `observed_version=3.15.01`, `verdict=fired`) gives at BASE `RECEIPT-MISMATCH S040` + `RELEASE_CLOCK: FAILED (… observed=29 fired=3 derived=15)`, exit 1, no traceback → the plan's predicate already calls that TYPED, so F1's before/after delta is 0. The plan's stated mechanism appears only with a receipt matching the lie: forging one (parsed_version `3.15.01`, verdict `fired`) gives at BASE `RELEASE_CLOCK: CLEAN (on_release=30 bound=30 unbound=0 observed=30 fired=4 derived=15)`, exit 0 — the leading-zero token reads as a *fired release* and the run stays CLEAN. The counting tool must supply that receipt (`--receipt FILE --receipt-sha SHA`); the fixture set need not change. Root cause: `version_is_named` checks the row's **anchor**, not the observation (`:341-345`, `:565-566`).

**F6 HIGH — same masking for the frozen C2 fixtures: "release-clocks.tsv edits only" cannot reproduce the frozen before-state.** Lowering S008–S011 to `3.13.2` (anchor=observed, `not-fired`) with the **pinned** receipt gives at BASE 4× `RECEIPT-MISMATCH` + `RELEASE_CLOCK: FAILED (… observed=26 fired=3 derived=11)`, exit 1 — never the "ACCEPTED (exit 0 CLEAN)" the predicate needs. With a **forged matching** receipt the same fixture is at BASE `RELEASE_CLOCK: CLEAN (… observed=30 fired=3 derived=15)`, exit 0 — the plan's premise. The plan's fixture sentence and its premise contradict; the tool must forge the receipt, and its EXACT test must assert the *derivation* category (else `RECEIPT-MISMATCH` satisfies it).

**F7 MED-HIGH — F4 is already "typed" at BASE.** The oversize feed entry is caught by `observe_one`'s `except (OSError, ValueError)` (`:822-823`): receipt `error` = free-text "Exceeds the limit (4300 digits) …", `verdict=null`, no traceback, exit 1 → the plan's predicate is satisfied at BASE. The frozen predicate must assert the finding's *category* for F1/F4; then the before-count `k` is 2 (F2, F3), not 4.

**F8 MED-HIGH — forced default-output changes the plan's Boundaries do not name.** Measured: (a) the new selftest count forces `SKILL.md:48` (`SC-CLOCK-SELFTEST`) **and** `PROVINCE.md:54` (`PV-CLOCK-SELFTEST`); if either lags, `python3 corpus/self-counts.py` prints `STALE SC-CLOCK-SELFTEST SKILL.md:48 claimed=85 live=79` and `SELF_COUNTS: STALE (claims=60 stale=1 unlocated=0 ambiguous=0)`, exit 1 → R25-02 (`claim-ledger.tsv:81`) breaks. **F9 MED — `claim-ledger.sh verify`'s summary key set is state-dependent.** CLEAN prints `CLAIM_LEDGER: CLEAN (claims=… deferred=… stamped=… ids=… cited=… labeled_ids=… orphans=… host_skipped=…)` (`corpus/claim-ledger.sh:1231`); FAIL prints a *different* key set (`:1222`). One red row (e.g. an un-migrated R21-02/R25-03 expectation) changes verify's last-line shape, not just a count. Every row must stay green.

**F10 MED — the observe→receipt contract constrains how C1 may report a feed defect.** `receipt_matches` (`:425-450`) closes the verdict vocabulary to {not-fired, fired, quote-located, quote-missing} and treats any `error` key as a mismatch. Recording the defect as a new `verdict` or in `error` makes the *next* default run report `RECEIPT-MISMATCH <row>` instead of the canonicality finding and leaves the receipt unusable. The finding must travel out-of-band; the pinned receipt `.ufo/waves/round-26/observe-2.json` (sha `13b8540c…`, `DEFAULT_RECEIPT_SHA256` `:29`) and its path (`:496-500`) must not change.

**F11 MED — the C1 guard belongs inside `numeric_version` and `parse_latest_version`, not in a validation branch.** Oversize tokens are converted at `:380`, in `feed_floors` (`:404`, which runs *before* any row check, so an oversize *anchor* crashes first) and in `parse_latest_version`'s `max(…, key=lambda v: tuple(int(part) …))` (`:760`). Read the bound from `sys.get_int_max_str_digits()` (4300 here, Python 3.14.8; configurable, min 640), not a literal.

**F12 LOW-MED — the plan's SemVer citation names a section the lane has not located.** The plan says "SemVer S042 §2", but S042 locates "§11 Precedence, item 11.2" and quotes §11.2 (numeric ordering) (`corpus/SOURCES.md:49`); the code comment says "SemVer 2.0.0 §11.2 (S042)" (`:371-373`). §2 is not the leading-zero clause and no registry row locates the numeric-identifier rule → the round-28 lesson would cite an unlocated section.

**F13 LOW — C1's scope ("an anchor, a table observation or a feed entry") is ambiguous about the registry anchor cells.** Scanning all 43 anchor cells is safe today (measured: zero non-canonical tokens; tokens are `1.17`,`4.6`,`11.2`,`13.1.6`,`2.0.0`,`3.15.0/1`,`2.2.0`,`2.7.1`,`3.13.3`,`8.23.0`) — but only under F1's predicate.
