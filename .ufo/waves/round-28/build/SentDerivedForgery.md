# C2 adversarial review — `release-clocks.tsv`

BASE: `3553d499577084a6c98d7078906017840bbf7b28`. Review is of the planned binding plus BASE's existing matcher/validation, not an integrated candidate.

## Findings

1. **MEDIUM — “named by” is an existential substring test, not an unambiguous feed-anchor identity.** BASE `corpus/release-clock.py:341-346` returns true on any matching substring and does not require a unique version or exact token boundary around SemVer suffixes (`-` is allowed after the match). Concrete case: add `2.1.0` as a second version in S034's `anchor` cell, retaining the existing `v2.2.0`; change derived S013/S022–S024 to `anchored_version=observed_version=2.1.0`, `not-fired`, and mirror those records in the fixture receipt. The planned check accepts because the modified anchor contains `2.1.0`; the Vault feed floor is then 2.1.0 while S012's existing observation is 2.2.0, so the floor check does not reject it. BASE S034 currently locates `v2.2.0` at `corpus/SOURCES.md:40`; the affected rows are `corpus/release-clocks.tsv:10,19-21`. Related single-token edge: an anchor containing `v2.1.0-rc1` also satisfies `version_is_named(anchor, "2.1.0")` because the matcher permits a hyphen after the core. **Frozen fixtures: no** — G1–G4 alter release-clock rows but leave SOURCES unchanged (plan `plans/round-28.md:61-68,93-101`). **Patch should close** this ambiguity: require the exact full canonical version token designated by the feed locator, and reject multiple distinct candidates rather than accepting any. Impact is a derived row calibrated to a stale, prerelease, or otherwise non-designated release.

2. **MEDIUM — a derived clock can be reassigned to an unrelated registered feed.** Changing only `feed_source_id` is already rejected as `BADFEED`: `corpus/release-clock.py:555-564` requires the selected registry URL to equal `feed_url`. But changing both fields passes that guard. For example, repoint S008 from S033/SOPS to S034/Vault, set its `feed_url` to S034's registered URL and its anchor/observation to 2.2.0 with `not-fired`, and mirror the receipt. The C2 version binding then succeeds against S034's `v2.2.0`, although S008 is a SOPS source. There is no checked source-ID-to-feed-ID association: `parse_sources` stores the anchor/kind/URL but not the registry scope (`corpus/release-clock.py:84-93`); the intended assignments are recorded in S033/S034 scopes (`corpus/SOURCES.md:39-40`). **Frozen fixtures: no** — they preserve feed IDs and URLs. **Patch should close** if that registry scope is the intended mapping: validate an explicit owner-clock/feed relationship (prefer a structured field over parsing prose) as well as URL equality. Otherwise name feed reassignment as an explicit limit. Impact is a clean but cross-product release-clock claim.

3. **LOW — SOURCES is the trust root, not an independently authenticated authority.** `parse_sources` reads `SOURCES.md` and copies the anchor cell directly (`corpus/release-clock.py:58-96`, especially 88); the planned check cannot detect coordinated edits to that same cell and the TSV. Example: change S033's anchor to include another canonical version and change S008–S011 to that value with matching observations/receipts. **Frozen fixtures: no** — they explicitly leave SOURCES untouched (plan `plans/round-28.md:61-68,93-101`). **Named limit**, not closable by this equality check alone: it assumes the registry anchor is trusted. If resistance to registry edits is required, authenticate the anchor independently (e.g. an independently maintained pin/provenance); copying it to another mutable local field is not sufficient. Impact is self-consistency being mistaken for source authenticity.

4. **LOW / no BASE bypass — stripping `derived:` alone falls back to the page anchor check.** BASE sets `is_derived` from `note.startswith("derived:")` and uses `version_is_named(sources[source_id]["anchor"], anchored)` otherwise (`corpus/release-clock.py:565-566`). The current derived owners do not name the exact derived release versions in their owner anchors: examples include S008–S011 (`corpus/SOURCES.md:14-17`), S013–S016 (`:19-22`), S021–S026 (`:27-32`), and curl S029 (`:35`, anchor names 8.23.1 while its derived row uses 8.23.0). Removing the prefix therefore becomes typed `INCONSISTENT`, not a C2 pass, for these BASE rows. **Frozen fixtures: no** — note text is unchanged in G1–G4. **Patch need not change the fallback** for this case; a small selftest for marker removal would preserve the fail-closed behavior. A simultaneous SOURCES anchor edit is covered by finding 3's trust-root limit.

5. **INFO — Unicode look-alikes alone do not provide a matching version.** The matcher escapes the requested version literally (`corpus/release-clock.py:345`), and BASE's version patterns use ASCII `[0-9]` (`:30-33,366-380`). For example, replacing a digit in a source anchor with fullwidth `０` does not make it name ASCII `0`; the C1 canonical-token rule also rejects non-ASCII version digits in a table/feed token. A Unicode look-alike prefix around an otherwise exact ASCII version does not change the identity of that ASCII version. **Frozen fixtures: no**, but no C2 remediation is indicated; an optional negative selftest could lock this down.
