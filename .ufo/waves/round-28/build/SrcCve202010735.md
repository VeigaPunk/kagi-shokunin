## Answer

- **Exact title.** NVD gives the record no descriptive title; its identity is `CVE-2020-10735`
  and the raw HTML `<title>` is `NVD - Home` (shell artifact). The CPython issue title is
  `CVE-2020-10735: Prevent DoS by large int<->str conversions`; its page `<title>` appends
  `· Issue #95778 · python/cpython · GitHub`.
- **Verbatim quote grounding the purpose** (NVD, Description, 18 words, literal in the decoded
  JSON, `grep -F` count 1): “a system could take 50ms to parse an int string with 100,000 digits
  and 5s for 1,000,000 digits” — locator `/vulnerabilities/0/cve/descriptions[lang=en].value`
  (`vulnStatus` Modified, lastModified 2026-10-14). The preceding clause names the cause:
  “In algorithms with quadratic time complexity using non-binary bases”.
- **Alternate quote** (CPython issue, `## Problem` first paragraph, 22 words,
  `rendered-text-v1 locate count=1`): “A huge integer will always consume a near-quadratic amount
  of CPU time in conversion to or from a base 10 (decimal) string” (sentence continues “with a
  large number of digits.”; quoted as a prefix).
- **Tier.** NVD = **B** — NIST aggregator, description is CNA-derived (“A flaw was found in
  python”), not CPython-authored. CPython issue #95778 = **A** — vendor-primary, and NVD itself
  tags it `Patch`.
- **Duplicate.** None (finding 6).
- **REJECT.** No reject for the *record*: the NVD Description does ground the quadratic
  int↔str-conversion purpose. REJECT the **detail HTML URL** as a registry source (finding 1) and
  reject any row claiming this source states the 4300 default or the `ValueError` contract
  (findings 4–5).
