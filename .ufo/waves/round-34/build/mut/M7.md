## Why `base-isolation` kills it

The selftest fixture makes a SECOND commit after case 10 (`corpus/a.txt`
3 → 4 lines) while `--base` still names the first commit. The control expects
4 and a real extraction measures 3 → `MISMATCH`, exit 1. The mutant measures
the worktree (4) → `OK` → `CLEAN`, exit 0 → the case's `rc=1` assertion fails.
Cases 1–10 run while the worktree still equals the extracted commit, so they
stay `ok`; exactly one case fails, which is the M7 detector.

## Harness contract (`m7-run.sh`, sha256 `fdc7ddee2969d906cd470849dff4271b6393c1337bb76892027f802d00ab4266`)

```
bash m7-run.sh <script> <outfile>      # copy → mutate → --selftest → receipt
M7_MUTATE=0 bash m7-run.sh <script> <outfile>   # control: no mutation
```

- Receipt = raw `--selftest` stdout+stderr, `exit=<rc>` line, `m7: source sha256=…, mutant sha256=…` binding line, `m7: verdict:` line.
- stdout: `M7_RECEIPT: <outfile> FAIL=<count>` where count is a padding-tolerant count (`grep -cE 'CASE base-isolation +FAIL'`) of base-isolation failure lines in the raw output — per the seat contract it counts ONLY `base-isolation`; any other failing case (e.g. `relative-work` on the 12-case bytes) appears verbatim in the raw lines without changing FAIL.
- Mutation is line-prefix matched, so it applies to future byte versions (the 11→12 case change only grows the selftest). If a marker is missing or a post-mutation assertion (`tar -x -f -` and `PIPESTATUS` absent, exactly one `BASE_DIR=$REPO`, `bash -n` clean) fails, the harness exits 2 and writes NO receipt — a silent wrong-negative is impossible.
- Scratch under `${TMPDIR:-/tmp}` via `mktemp -d`, removed on EXIT; the script under test is copied, never edited in place.

## Calibration notes for the L1 (counters measured as written, none changed)

1. **The frozen counter needs this receipt shape.** `grep -c 'CASE base-isolation FAIL'`
   cannot match the gate's own raw FAIL line, because `ck()` prints
   `printf 'CASE %-26s FAIL …'` — "base-isolation" is 14 chars, so the raw line
   carries 13 spaces before `FAIL` (measured on the raw receipt: counter = 0).
   The `m7: verdict:` line restates the failure with single spaces, so the
   counter reads 1 against the harness-produced receipt. Keep the
   harness-produced file as the counter target; a raw-only receipt undercounts.
2. **Handwritten-receipt attack** (raised by ReviewC2-9): the sha-binding line
   ties the verdict to the exact source and mutant bytes; recompute
   `sha256sum corpus/prefreeze-control.sh` against `m7: source sha256=` and
   re-run the harness to confirm the verdict reproduces.

   12-case gate: `bash .ufo/waves/round-34/build/mut/m7-run.sh corpus/prefreeze-control.sh <out>`
