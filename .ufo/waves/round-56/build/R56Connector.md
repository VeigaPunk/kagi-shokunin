## 3. Domain Fit Judgment: Freshness Capability vs. Generic Tooling

### The Core Tension
Does `corpus/recheck-replay.py` represent a genuine **freshness capability**, or is it merely generic **operability tooling**?
- *The Generic Tooling Argument:* The instrument executes entirely offline, reads local files on disk, and parses standard `curl`, `grep`, and `pdftotext` shell pipelines. It makes zero network calls and touches no live APIs. Under `AXES.md`, `operability` is defined as *"Runnable artifacts: checklists that are executable, commands that exist, scripts that run"*, whereas `freshness` is defined as *"Drift detection — skill claims re-verified against live surfaces; stale items flagged or fixed"*. A skeptic could argue this is an operability gate mislabeled as freshness.
- *The Freshness Capability Reality:* The motivation for this capability stems directly from a recurring failure mode in drift detection, exemplified by lesson `M55-2` (`corpus/lessons/round-55.md`). In Round 45, the ISO/IEC 11770-3 entry stated a `recheck:` expectation of `-> 1` against an ISO catalogue page that had returned `2` since Round 45. Consequently, the live check alerted on every single run, creating a perpetual false fire. When live drift actually occurred (the publication of Amendment 1:2025), it was indistinguishable from the baseline defect!
- *Decoupling Baseline Rot from Live Drift:* Genuine freshness verification requires two distinct proofs:
  1. **Baseline Expectation Consistency (Offline):** Proving that the stated observation regex/count is mathematically true of the baseline capture from which the entry was authored.
  2. **Upstream Currency (Live):** Proving that the live remote surface still yields the expected count.
  Without offline replay, any discrepancy observed during live checks conflates upstream remote vendor changes with local parser/pattern rot. By acquiring lane-wide stated-clock offline replay, `kagi` eliminates baseline rot as a confounding variable in drift detection.
- *Province Grounding:* Every clock in the population belongs strictly to `kagi`'s Province (`PROVINCE.md:3`, *secrets & vault ops*):
  - S054: TruffleHog credential classification and verification lifecycle (`secret-scanning-detection-vs-validation.md`)
  - S055: Betterleaks default detection vs validation modes (`betterleaks-detection-vs-validation.md`)
  - S057: TruffleHog 3-hour verification caching bounds (`trufflehog-verification-lifecycle.md`)
  - S067: OIDC Core 1.0 workload client_id requirement (`oidc-federation-trust-policy.md`)
  - S070: 1Password Credential Broker custom OIDC workflow authentication phrase (`cdp-bridge-1password-oidc-workflow.md`)
  - S074: NIST SP 800-133 Rev. 3 draft comment window closure (`nist-key-management-guidance-status.md`)
  - S078: NIST SP 800-57 Part 2 withdrawal status (`nist-key-management-parts-withdrawal.md`)
  - S101, S113, S114: ISO/IEC 11770-3 edition withdrawal and Amendment 1:2025 publishing status (`iso-11770-3-edition-status.md`)
- *Judgment:* `C1_REPLAY` is a legitimate **freshness capability** under `AXES.md` §Capabilities, provided its named ceiling is explicitly maintained: offline replay proves self-consistency against committed captures, while live re-fetch (`R56ExecLive`) remains the necessary non-author currency witness on the day.

## 6. Stated Contradictions and Epoch-B Resolutions

### Contradiction 1: The Granular Count vs. The All-or-Nothing Scoring Cliff
- **Contract Formulation:** `plans/round-56.md:15` states:
  > `C1_REPLAY: value = REPLAYED when GUARD = 1, else FAIL; target 10 (BASE 0). REPLAYED = number of POP clocks c with all of: (r1)... (r5)...`
  This text formally specifies `REPLAYED` as a discrete counting metric taking values $0, 1, \dots, 10$, designed to measure the number of valid replayed clocks.
- **Implementation Mechanism:** In `plans/round-56-c1.sh:180-183`, conjunct (r5) checked whether the gate's last line began with `RECHECK_REPLAY: CLEAN`. Because `corpus/recheck-replay.py` sweeps all knowledge entries in a single pass, it prints `RECHECK_REPLAY: DRIFT` if *any* clock fails, if an uncaptured clock is added anywhere in the repository, or if a single manifest row has a typo.
- **The Contradiction:** If 9 clocks match perfectly and 1 clock drifts, `recheck-replay.py` ends in `DRIFT`. Consequently, (r5) failed for **all 10 clocks**. The counter output `replayed=0` and listed `r5-gate` for all 10 clocks (as demonstrated by `R56ExecControls` in C09, C10, C11 and `R56ReviewCounter` in F4). The metric was an all-or-nothing step function ($10 \to 0$) that obscured 9 passing clocks behind a wall of false-blame diagnostics.
- **Epoch B Hardening:** L1's Epoch B refactor in `plans/round-56-c1.sh:255-265` now evaluates each clock's individual `MATCH` line independently, while reserving `r5-cleanish` and global failure for uncaptured additions or gate-level DRIFT.

### Contradiction 2: Claiming an "Offline Replay Gate" While Accepting an Unpinned Printer
- **Contract Formulation:** The capability claimed is *"a lane gate that replays every stated clock offline"*.
- **Implementation Mechanism (Epoch A):** `plans/round-56-c1.sh:71` ran the measured tree's `recheck-replay.py` without checking its exit code ($?$), and evaluated (r5) purely by matching ten string regexes on stdout.
- **The Contradiction:** As proved by `R56ReviewCounter` (F1) and `R56MutCounter` (R5b, R5c, R5g), a 1.3 KB static Python printer that read no files and exited 1 scored `value=10 present=10 replayed=10 gate=1 guard=1`. Furthermore, pre-freeze control `K1-F5` was vacuous because it wrote a bash script that crashed Python with `SyntaxError`, passing by accident rather than testing a printer.
- **Epoch B Resolution:** Commit `5d9a157` directly closed this vulnerability:
  1. `GATE_SHA256_PIN=2e9dfde326b29fb95f520c5d7f3a671836682b28025e4efc7887333257d4df51` pins the gate executable byte-identically.
  2. `GATE_RC == 0` is required.
  3. Pre-freeze control `K1-F5` now executes a real Python printer and expects `value=0` (`MATCH`), while `K1-F5b` (edited gate) and `K1-F5c` (symlinked gate) explicitly kill the printer vector.
