### Instructions (how the capability is run)

- **Run the gate**: `python3 -I -B corpus/recheck-replay.py` from the lane root, or `--root DIR` over an extracted tree. It is read-only and makes no network call.
- **Prove the gate**: `python3 -I -B corpus/recheck-replay.py --selftest` — 13 cases, exit 0 with last line `RECHECK_REPLAY_SELFTEST: PASS (13 cases)`.
- **Run the claim counter**: `bash plans/round-56-c1.sh <revision>` or `--tree DIR`. Admission parses the `C1_REPLAY: value=<token>` line and requires `value=10`, `guard=1`, `present=10`; the counter exits 0 for `value=FAIL` and `value=0` as well, so a rc-only harness is a defect (R56ReviewCounter F9).
- **Add a clock**: one column-1 `recheck:` line carrying a backticked `curl …` command in an accepted form followed by `-> N` or `-> count=N`; one row of `corpus/recheck-captures.tsv` (`id`, `url`, `body_path`, `fetched`, `http_status`, `bytes`, `sha256`); the id must name exactly one 11-cell `mined` `corpus/SOURCES.md` row whose source cell contains the URL; the body committed without any HTTP status line or `set-cookie:` line. Then run the gate and record the MATCH line.
- **Replace a capture**: public GET only (`curl -o`; never `-D`/`-i`), recompute `bytes`/`sha256` from the stored body, update the manifest row, re-run the gate; the replacement is a reviewed commit. The live run of the command is the currency check; the capture only makes the stated expectation checkable offline.
- **Repair a MISMATCH**: re-run the statement live. If the page moved, refresh the capture and row; if the entry's expectation was wrong, correct the N and record the date (never delete the clock silently). `NO-CAPTURE` means the clock is outside the gate (it cannot print CLEAN); `UNSUPPORTED` means the command form is outside the three accepted forms (the gate also refuses CLEAN); `BAD-CAPTURE` names the path/digest/unconfinement/header defect; `TOOL` means a filter tool is missing or failed.

### Bounds (named, measured at `42070de`)

1. **Committed bytes only.** A MATCH says the statement is true of the capture, not that the live page still says it. The live run is the freshness check (this round: 10/10 true on 2026-11-07 by R56ExecLive).
2. **Population is knowledge entries only.** `corpus/knowledge/*.md`, column-1 `recheck:` lines; lessons and every other file are outside the gate (round-55 lesson §Routed 2 measured the same population). A clock added to a knowledge entry without a manifest row turns r5/CLEAN off and reads `value=0` (M56-7 / ReviewGate F3).
3. **Three accepted forms only.** `curl <accepted flags> '<URL>' | grep -c '<BRE>'`; `… | pdftotext -layout - - | grep -c '<BRE>'`; `… | python3 corpus/rendered-text-v1.py locate /dev/stdin '<quote>'`. Any other form is `UNSUPPORTED`, and the gate cannot print CLEAN (fail-closed). The counter refuses a restated N with a trailing letter only partially (`-> 1x` reads as 1; ReviewCounter F3).
4. **`grep -c` counts matching lines, not occurrences.** S057's phrase occurs twice on line 12 of the minified payload and the stated count is 1; the replay uses host `grep -c -e '<BRE>'` (BRE/locale semantics). R56ReviewGate measured identical counts under `LC_ALL=C` and `C.UTF-8`; the host grep is `pi-uu-grep 0.2.0`, not GNU grep (R56ExecLive).
5. **Capture provenance is not fully raw-byte reproducible.** The fetch receipt plus a non-author re-fetch reproduced 9/10 bodies byte-identically; S074's raw body gives a different sha256 at the same 45351 B on every fetch (five same-day digests from R56ScoutSources), with the clock phrase on unchanged line 435 and the declared normalizer's digest stable at `955dd8665388946280b67fdcbd9e9c7cfa3d5343b54f223daf5cba40ebeb7fab` (5636 normalized bytes). A raw-sha reproduction ceiling fails on S074 and only S074 (M56-2).
6. **A hand-written capture with a self-consistent manifest row scores** (named ceiling in the plan and the gate docstring); provenance is the fetch receipt plus a non-author re-fetch, not a cryptographic proof of origin.
7. **Manifest `fetched` and `http_status` are recorded but never read** by the gate or the counter (ReviewGate F4; verified in `corpus/recheck-replay.py:143-176`, `plans/round-56-c1.sh:202-218`). A 404 body with a consistent sha would score if a clock's filter matched it.
8. **Header refusal is a literal column-0 prefix test, not a header parser.** `re.match(rb"HTTP/\d", data)` / `re.search(rb"(?im)^set-cookie:", data)`: a `curl -v` trace whose lines start `< ` is not refused (ReviewGate F1; M56-6). There is no commit-time hook (`git config core.hooksPath` empty, `.git/hooks` has 0 non-sample files — R56Sentinel F1).
9. **The gate executes code from the tree under test.** The locate form runs `<root>/corpus/rendered-text-v1.py`, and counter r5 runs the measured tree's `recheck-replay.py`; a doctored tree can print its own CLEAN (R56Sentinel F5, R56ReviewCounter F1/F7). Admission is only saved from this by r4 replaying with BASE's normalizer on the pinned body (counter r4), not by r5.
10. **The counter's r5 is a text check, not a gate check.** A 1322-byte Python printer with zero reads placed at the gate path scores `value=10 … guard=1` (R56ReviewCounter F1; R56Scribe reproduced with a 12-line printer, sha256 `d04cae5a25bfaf457a03ddcc78c42991d53b60bb2070dd51be908e687a167a9a`, 0 `read` occurrences, same reading). The gate's own execution and selftest are real when run directly; the *counter's admission* of the gate is not yet bound.
11. **Symlinked knowledge entries are skipped silently by the gate**, so its summary can read `CLEAN (clocks=9)` on a tree with a symlinked entry (ReviewCounter F6 / ReviewGate F3). The counter's r1 refuses the same shape (`present=9`), so `value=10` is not forgeable that way.
12. **Tool and path trust.** Missing `python3`/`grep`/`pdftotext` is SETUP/TOOL; grep runs with a 60 s timeout, pdftotext/locate 120 s; r4 and the gate trust PATH-resolved tools (R56ReviewCounter F11). The counter needs a git repo carrying BASE for its normalizer (`SETUP base-normaliser` in a lone copy; ReviewCounter F10).
