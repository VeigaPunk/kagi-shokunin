## Reading note
probe2/probe3 were written before the endpoint shapes were known; their
"destroy" legs used an accessor read from a lookup call instead of the
generated secret-id response, so those two lines are probe bugs, not binary
behaviour. probe4 is authoritative for the destroy leg and for the working
bind_secret_id=false combination. The three facts that matter:
  F1 default role: role_id-only login -> HTTP 400 "missing secret_id".
  F2 bind_secret_id=false ALONE -> HTTP 500 "at least one constraint should be
     enabled on the role"; with secret_id_bound_cidrs=127.0.0.1/32 present the
     same update succeeds and role_id-only login issues a token (rc 0).
  F3 secret-id-accessor/lookup returns cidr_list, creation_time,
     expiration_time, last_updated_time, metadata, secret_id_accessor,
     secret_id_num_uses, secret_id_ttl, token_bound_cidrs and no secret_id
     value; destroy of the accessor makes the still-valid secret_id login read
     HTTP 400 "invalid role or secret ID".
