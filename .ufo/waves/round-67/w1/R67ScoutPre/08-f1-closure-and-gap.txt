  blind-gate.txt contains one CLEAN verdict line and nothing else. It is byte-identical

  tell from the file which tree produced it, and cannot tell that it was a repointed
  copy at all.

WHY THIS MATTERS (and is not pedantry): the WHOLE POINT of the blindness witness is that
the repointed copy prints the SAME verdict as the clean tree — I measured exactly that:
  BASE gate on the clean tree       -> SOURCES_CENSUS: CLEAN (rows=156 …)  rc=0
  BASE gate on the repointed copy   -> SOURCES_CENSUS: CLEAN (rows=156 …)  rc=0
  (the two verdict lines are the same string, so a verdict-only receipt cannot carry
   the witness). The evidence that a MUTATION was applied has to be in the receipt's
   provenance — the tree it was measured on and what was mutated — because it cannot be
   in the verdict.
This is the same standard the round applies to L6 in this very round: leg L6's repair is
"commit a reconstructed receipt whose header names its provenance". blind-gate.txt is the
round-67 analogue of a receipt with no provenance header, and it is cited by a frozen
plan as the plan's own motivating evidence.
