replaced by a marker-writing program; run

(The BASE comparison uses `git show 076701a:corpus/sources-census.sh`; BASE
contains zero `python3` invocations, so it cannot execute the tree's file.)

## P-liar — the realistic one-line liar does NOT reach the target

A tree whose normalizer is the real one plus `count = max(n,1)`:

```
=== GATE on the tree (--root), with the tree's liar ===
FINDING SC_CAPTURE id=S156 quote-not-located
SOURCES_CAPTURES: FAILED (defects=31 path_rows=36 bound=36 located=5 prose=120)
SOURCES_CENSUS: FAILED (findings=31 rows=156)

=== GATE's own --selftest on the tree (SCRIPT_DIR = the tree) ===
SOURCES_CENSUS_SELFTEST: PASS (88 cases)

=== C1 COUNTER on the tree ===
c1-readthrough: derived path_rows=36 bound=36 located=5 prose=120 malformed=0
c1-readthrough: guard-a verdict=FAILED rc=1 … gate_fields=differ adjacent=True population=36
C1_READTHROUGH: bound=36 located=5 caught=6/6 guard=0
```

Honest negative result, reported as such: a liar that reports `count=1` for
*every* quote is refused by the gate, because the gate's own `--selftest`
runs against the tree's normalizer and its `capture-quote-garbage` case
fails. The defect in V-1 is therefore specifically the class the instruments'
own sentinel strings exempt.

## P-selective — the decisive case (V-1)

Method: tree whose normalizer is the real one plus an exception that reports
`count=1` for every quote EXCEPT two sentinels the instruments themselves
place in the tree (the gate's selftest garbage quote and the counter's
`zzc1notlocatedquotezz`); every rendered-text-v1 path row's quote replaced
by a non-locating string.

```
=== GATE on the tree (--root) ===

SOURCES_CENSUS: CLEAN (rows=156 …)

=== GATE's own --selftest (guard-b source) ===
SOURCES_CENSUS_SELFTEST: PASS (88 cases)

=== C1 COUNTER on the tree ===
c1-readthrough: derived path_rows=36 bound=36 located=36 prose=120 malformed=0
c1-readthrough: guard-a verdict=CLEAN rc=0 captures=SOURCES_CAPTURES: CLEAN (path_rows=36 bound=36 located=36 prose=120) derived=path_rows=36 bound=36 located=36 prose=120 gate_fields=match adjacent=True population=36
c1-readthrough: guard-b selftest rc=0 cases=88
c1-readthrough: guard-c base-gate-on-repoint rc=0 verdict=SOURCES_CENSUS: CLEAN (rows=156 …)
c1-readthrough: guard-e prose_rows=120 prose_findings=none gate_prose=120 derived_prose=120
```

The frozen target is reached on a tree whose declared quotes do not locate.

## P-remedy — the one-line remediation closes the cross-check (V-1)

Method: copy the counter to scratch; change only
`script = os.path.join(tree, "corpus/rendered-text-v1.py")` →
`os.path.join('<lane>', "corpus/rendered-text-v1.py")`; run both counters on
the P-selective liar tree. The lane's counter was not edited.

```
=== UNPATCHED counter (tree's liar drives both sides) ===
c1-readthrough: derived path_rows=36 bound=36 located=36 prose=120 malformed=0
c1-readthrough: guard-a verdict=CLEAN rc=0 line=frozen derived=… located=36 … gate_fields=match adjacent=True
C1_READTHROUGH: SETUP base-gate-unavailable git-show 076701a1…

=== PATCHED counter (derivation uses the lane's own normalizer) ===
c1-readthrough: derived path_rows=36 bound=36 located=5 prose=120 malformed=0
c1-readthrough: guard-a verdict=CLEAN rc=0 line=frozen derived=… located=5 … gate_fields=differ adjacent=True
C1_READTHROUGH: SETUP base-gate-unavailable git-show 076701a1…
```

With the patch the derivation reads `located=5` while the tree's gate reads
`located=36`; the two disagree (`gate_fields=differ`), so guard (a) is a real
check. Both runs stop at the same unrelated `SETUP base-gate-unavailable`
(the scratch tree has no `.git`, so `git show <BASE>:…` cannot resolve); the
guard-(a) line above is the leg under test and it reads as claimed.
