plans/round-68.md reason set: `capture-token` (a non-pure cell

or a token that does not resolve in-lane).

  '~/.ufo/waves/round-67/capture/S166.body'      contains=True  prefix=False
  '//etc/passwd'                                 contains=False prefix=False
  '~/S166.body'                                  contains=False prefix=False
  './.ufo/waves/round-67/capture/S166.body'      contains=True  prefix=False
  '.ufo//waves/round-67/capture/S166.body'       contains=False prefix=False

A `~/`-form and a `//`-form that name a .ufo/waves/ file are
named by the plan's `capture-token` reason, so the gate MUST use
the CONTAINS reading (a token CONTAINING .ufo/waves/), not a
prefix test.  Under a prefix reading the `~/` and `//` forms are
prose and never read -- the fail-open the widened gate must not have.
